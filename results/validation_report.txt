Research Validity Review
Air Quality Prediction
Audit date: 2026-11-15

Scope
-----
Reviewed src/preprocess.py, src/experiment.py, main.py, the prepared dataset,
saved test predictions, model comparison table, experiment report, and saved
best-model pipeline. Checks were independently performed against the stored
data and results. The model was loaded for verification but not retrained.
No experiment metrics, predictions, datasets, or model files were changed.

Overall assessment
------------------
The implemented target construction, chronological split, model preprocessing,
common-sample evaluation, persistence baseline, and metric calculations pass
the requested checks. No target leakage or metric calculation defect was found.

Checks performed
----------------

1. Next-hour target and station isolation: PASS

     then recomputed PM2.5_next_hour with a station-grouped shift.
   - Verified every one of the 412,017 prepared targets equals PM2.5 from the
     same station exactly one hour later. No target crossed station boundaries.
   - The combined data has 420,768 rows across 12 stations. There are no
     duplicate station/datetime keys or internal hourly gaps.
   - The 8,751 rows without a valid target were excluded; the prepared target

2. Chronological train/test split: PASS
   - src/experiment.py splits on target timestamps, without shuffling.
   - The cutoff is 2016-05-12 09:00. Training has 329,466 records with target
     times ending at 2016-05-12 08:00; testing has 82,551 records with target
     times beginning at 2016-05-12 09:00.
   - Checked all 12 stations: training target times precede test target times.

3. Future information and target leakage: PASS, with an operational condition

   - The target is independently verified to be the following hour. No
     future-hour observations are used as model inputs.
   - This forecast setup assumes the current-hour pollutant and meteorological
     measurements are available when the next-hour prediction is issued.

4. Imputation and categorical encoding: PASS
   - Numeric median imputation, the linear model's scaling, and station

   - Source code fits each pipeline on x_train before predicting on x_test.
   - Independently checked the saved Random Forest pipeline: its numeric

   - Missing feature values are retained until pipeline transformation; no

Research limitations and recommended fixes
-------------------------------------------
1. Holdout-based model selection:
   Random Forest is selected as the winner using the same test-set RMSE that is
   reported. This is not feature leakage, but selecting the winner on the final
   test set introduces model-selection optimism; the reported winner's test
   score is no longer a fully independent final estimate.
   Recommended fix for a future, separately recorded experiment: select the
   model using a chronological validation period or rolling-origin validation
   within the training period, refit the selected model on the full training
   period, and use the latest 20% only once for final evaluation. Existing
   results were not changed.

2. Scope of generalization:
   This is one chronological holdout from the same 12 Beijing stations and
   2013-2017 dataset. It does not establish performance at unseen stations,
   other cities, or later periods. Consider a separate station-held-out or
   external-time evaluation if those are research claims.

3. Forecast input availability:
   The experiment uses current-hour pollutant and meteorological readings.
   Confirm these readings would be available at the intended forecast issue
   time. The pipeline does not forecast future weather or pollutant inputs.

4. Feature-importance interpretation:
   Tree impurity importance is model-specific and can favor continuous or
   high-cardinality features. It describes the fitted models, not causality or
   statistical significance. Consider permutation importance on held-out data
   as a complementary analysis.

5. Single evaluation split:
   No confidence intervals or repeated rolling-origin estimates are reported.
   Treat small score differences as descriptive rather than evidence of a
   statistically reliable advantage.

Conclusion
----------
The requested implementation checks pass for the stored experiment. Random
Forest has the lowest RMSE in this comparison, but its selection on the same
holdout is a limitation to address before presenting that score as an
independent final estimate. This review did not rerun training or modify
experimental outputs.
